# Staging: agent signup, remote MCP and Claude/Codex packaging

**Status: Liam approved implementation on 1 November 2026, then authorised continuing through all slices without approval pauses. Commit/PR each slice separately; external configuration, production and spend boundaries remain. Size: XL overall.**

## Goal and boundaries
An agent discovers Vantage, starts a restricted trial, reads useful conversation evidence and prepares private text. A person signs in with **existing Neon Auth**, reviews the request and claims the workspace. Normal Claude Code/Codex connections also support browser login using OAuth 2.1 + PKCE (a check that binds the login approval to the client that started it).

- **Staging only**, `AGENT_REGISTRATION_ENABLED=false` by default; also require `VANTAGE_DEPLOY_ENV=staging`. Even an accidentally enabled production flag must not enable access. No production deployment, migration, secret changes or WorkOS AuthKit.
- Anonymous registration only; reject `service_auth` and externally supplied `identity_assertion`/ID-JAG registration. Anonymous auth.md still returns a **Vantage-signed assertion**, exchanged for a short-lived access token; that is not accepting an external identity provider's ID-JAG.
- Allowed: workspace-bound reads and generation of private text. Never post, reply, DM, email contacts, publish, change billing, install credentials or access other workspaces. Claiming cannot expand an agent's access to the owner's other projects.
- Client zero is **contextfor.dev**, with evidence for Liam's case study. That production domain is the product being researched, not permission to enable registration there. Use the real staging hostname; a staging subdomain under contextfor.dev requires separate DNS/configuration approval.

## Trial and abuse policy proposed for approval
- One workspace/registration, one explicit setup scan, seven days; 15-minute access tokens, ten-minute claim codes and at most ten draft attempts/trial. Assertion lifetime cannot exceed the trial. Assertions remain sensitive credentials, even though access tokens expire sooner.
- `RADAR_LIMITER` throttles trusted edge IPs and registration IDs. Database counters enforce durable hard quotas, bounded poll frequency and a shared registration ceiling; rotating registration IDs must not reset IP/global allowances. Exact thresholds are confirmed in AR00.
- Trial spend defaults to **$0**. Scoring/drafting can cost money: return a clear unavailable/budget message until Liam approves a small staging allowance. Listing tools never secretly starts scans. The one initial scan belongs to server-owned trial setup with an explicit request; agent tokens never receive general scan/write permission.
- Expiry is checked on every action. Cleanup cancels/fences trial jobs and removes temporary data/storage; preserve only a minimal, time-bounded audit record. No credentials, raw IPs or private content in logs/public discovery. Model/provider calls use existing reservations and ledgers.
